| ჩვეულებრივი გზა | ჩემი გადაწყვეტა | დაზოგილი |

| მარაგებში კრიტიკული ნივთის ძებნა | Dashboard-ზე ცალკე ბლოკი + 🔔 შეტყობინება | 3–4 კლიკი |

## 3. ინტერაქციული მდგომარეობები ამ სცენარისთვის

### 3.1 Loading
- **შეკვეთების ცხრილი** — Skeleton (5 ხაზი);
- **მომწოდებლების სია (dropdown)** — dropdown-ში „იტვირთება..." + პატარა Spinner;
- **„გაგზავნა" ღილაკი** — Spinner + „იგზავნება...", ღილაკი და ფორმა იბლოკება.

### 3.2 Empty
| სიტუაცია | ტექსტი | მოქმედება |
|---|---|---|
| შეკვეთები არ არის | 📋 „ჯერ არცერთი შეკვეთა არ შეგიქმნიათ." | [+ პირველი შეკვეთის შექმნა] |
| ფილტრით ვერაფერი მოიძებნა | 🔍 „ამ სტატუსით შეკვეთა ვერ მოიძებნა." | [ფილტრის გასუფთავება] |
| კრიტიკული მარაგი არ არის | ✅ „ყველა ნივთის მარაგი ნორმაშია!" | — |
| ფორმაში ნივთი არ არის დამატებული | „დაამატეთ მინიმუმ ერთი ნივთი" (ცხრილის ადგილას) | [+ ნივთის დამატება] |

### 3.3 Validation Feedback (ცოცხალი)
| ველი | როდის ჩნდება | შეტყობინება |
|---|---|---|
| მომწოდებელი | „გაგზავნა"-ზე, თუ ცარიელია | „აირჩიეთ მომწოდებელი" |
| თარიღი | არჩევისთანავე, თუ წარსულია | „თარიღი არ შეიძლება იყოს წარსულში" |
| რაოდენობა | წერისას, თუ 0 ან უარყოფითია | „რაოდენობა მინიმუმ 1" |
| ფასი | ველიდან გასვლისას | „ფასი უნდა იყოს 0-ზე მეტი" |
| იგივე ნივთი ორჯერ | მეორედ არჩევისთანავე | „ეს ნივთი უკვე დამატებულია" |

**ჯამი** ითვლება ცოცხლად — რაოდენობის ან ფასის შეცვლისთანავე.

**დაუმახსოვრებელი ცვლილებები:** თუ ფორმა შევსებულია და მომხმარებელი „უკან"-ს აჭერს → დადასტურება: „ცვლილებები არ შეინახება. გასვლა?"
